# Site architecture recipes

Treat these as hypotheses to verify against the current artifact.

- **Static HTML:** mirror assets, preserve paths, and test from the intended local origin.
- **ES modules:** `file://` often blocks module fetches. Prefer a tiny local server or a build that bundles modules; do not contort source solely to permit double-click launch unless that is a requirement.
- **Vite/React SPA:** capture the built asset graph or rebuild from source. Verify client routes and root-relative assets under the archive base path.
- **Next.js/App Router:** inspect both DOM asset references and serialized payloads that hydration can reintroduce. Disable or rewrite server-only routes explicitly.
- **Next.js with Turbopack:** lazily loaded chunks appear in the bundles as bare relative strings (`"static/chunks/name..js"`) with no leading slash and no markup reference. A scanner that only matches paths beginning with `/` misses them, and the archive throws `ChunkLoadError` into the app's own error boundary. Scan for the relative form too, then rescan until a round finds nothing new: the tiers are not always two deep, and each newly fetched chunk can name more.
- **Do not rewrite URLs inside a Next hydration payload.** It arrives as a run of `self.__next_f.push([1,"…"])` string fragments split at arbitrary byte offsets, so one URL can straddle two fragments. Stripping a query string inside one fragment leaves the tail behind (`.js?dpl=…mpBT` becomes `.jspBT`) and hydration dies. Let the local server ignore query strings instead, and assert after every build that each `/_next/` reference resolves to a file — allowing a truncated reference that is a prefix of a real filename, which is a legitimate fragment split.
- **Astro, statically built:** the HTML ships complete, so the page paints even when every script is dead — a screenshot proves nothing. Assets live under `/_astro/` with content hashes; Vercel adds a `?dpl=dpl_…` cache-buster that is safe to strip. Follow imports transitively out of the per-component `*.astro_astro_type_script_*.js` entry points, and check the `<style>` blocks inlined in `<head>`, which reference images by `url("/_astro/…")` HTML-escaped as `&quot;`.
- **Rewriting a root-absolute path to a relative one breaks ES module specifiers.** `posixpath.relpath("/_astro/a.js", "_astro")` yields `a.js`, and a bare specifier is illegal in a module: "Relative references must start with either `/`, `./`, or `../`". Every dynamic import throws, the page still looks right, and all the behavior is gone. Re-prefix `./` on any rewritten specifier in an `import`/`export … from`/`import()` position.
- **Rewrite every candidate in a `srcset`, not just the first.** A regex anchored on `src="` matches only the leading URL; the `2x` and `3x` candidates stay root-absolute and are never fetched, so the archive is silently broken on Retina displays only. Parse `srcset` as its own comma-separated list.
- **Images inside a closed `<dialog>` are never fetched**, so a completeness check that scrolls the document still reports them as pending. Open every `dialog:not([open])` before the image audit, then close it again.
- **Client-rendered Next.js App Router:** when the served HTML carries `BAILOUT_TO_CLIENT_SIDE_RENDERING` and is a few tens of KB, it does not contain its own asset graph — the chunk loader resolves it at runtime. Do not infer the inventory from the markup. Load the live page in a headless browser first and record every request it makes, use that as the seed list, then follow references transitively until a round finds nothing new. The transitive pass is not redundant: it catches assets the stylesheet needs but the current page never triggers, such as an italic webfont on a page with no italics.
- **Prefer serving root-relative paths over rewriting them.** A small local server that resolves `/_next/...` and ignores query strings avoids touching the RSC payload at all, and handles cache-busters (`?v=5`, `?dpl=…`) that are not part of any filename on disk. Check how many `self.__next_f.push` fragments there are before assuming the straddling hazard applies — a single-fragment payload is safe to edit, but there is rarely a reason to.
- **Next.js flight rows are length-prefixed.** The RSC payload embedded in the HTML as `self.__next_f.push([1,"…"])` uses rows of the form `<id>:T<hex-length>,<text>`. Any substitution inside it — swapping an origin for a local one — that changes byte length truncates the stream. The symptoms are `Error: Connection closed` and React error #418, and the page renders a fraction of its content while still looking plausible. Either make every replacement the same byte length (`https://alembic.space` and `http://127.0.0.1:8100` are both 21 characters, which is not a coincidence worth relying on twice) or do the remapping at runtime in the shim instead. Length-preserving pairs are worth asserting in code.
- **Same-length rewriting can still break hydration when the client derives text from a URL.** Swapping `https://` for an 8-byte local prefix (`/_ext__/`) keeps flight rows intact, but if the page renders Markdown on the client (`![alt](https://…)`), the renderer may treat only absolute `https` URLs as images and print something else for a relative one: React #418 (`args[]=text`) on just the pages with images, while pages without them pass. Rewrite only markup outside `<script>` and CSS, leave the flight payload and API JSON untouched, and map the media origin at runtime in the head shim by wrapping `Element.prototype.setAttribute` and the `src`/`srcset` setters of `HTMLImageElement`, `HTMLSourceElement` and `HTMLLinkElement`. Bisect a hydration error by serving with each serve-time transform off in turn. Working server: `websites/deimos-evilrabbit-com/serve.py`.
- **Cross-origin links with no same-length local form** are the residue of that rule. Redirect them on use — a capture-phase `click` listener plus a `window.open` wrapper — rather than editing the markup.
- **Cloudflare may ignore the `RSC` request header** and return HTML where the flight payload was expected, so `<route>.txt?_rsc=…` prefetches cannot be captured directly. They can be reconstructed: concatenate the `__next_f.push` chunk strings from the already-captured page, in document order, and serve that as `text/x-component`.
- **Lazily-loaded chunks exist only in webpack's chunk-id map.** `r.u = e => "static/chunks/" + e + "." + ({…})[e] + ".js"` in `webpack-*.js` is often the sole record of chunks no HTML references. Some builds add an id-remap table (`({162:"b478a885"})[e] || e`), so the filename cannot be derived from the id alone — evaluate both tables. Missing these leaves an app that looks complete until one panel is opened.
- **Next.js Server Actions are a hidden live dependency.** A form with `$ACTION_REF_*` / `$ACTION_KEY` hidden inputs POSTs back to a server runtime that does not exist in an archive. Setting `disabled` does not hold, because React re-enables the control when it hydrates. Intercept `submit` in the capture phase on `window` — that runs before React's delegated handler — and have the local server answer POST with 501 as a backstop for scripting being off.
- **three.js `DRACOLoader` fetches its decoder from `https://www.gstatic.com/draco/versioned/decoders/<ver>/`** at runtime, only when a compressed `.glb` loads. No string in the HTML points at it and a static crawl misses it; the model just never appears. Capture `draco_decoder.wasm`, `draco_wasm_wrapper.js` and `draco_decoder.js` for that version and map the origin locally.
- **Stripe marketing pages (`b.stripecdn.com/mkt-statics-srv`)** load components through a JSON `data-js-script-registry` and a loader that refuses any URL not on `stripecdn.com`; after mapping hosts locally, every module is silently rejected (one `Uncaught (in promise) Array(n)`). Open that host check, then drop Sentry, UniversalChatInitializer, Notification, ScrollDepthTracker and MonitorWebVitals from the registry. Analytics turns off at `inProduction:!1` on the reporter; the remaining beacons (`r.stripe.com`, GTM and PrivacyCompliance iframes, Sprig) are easier to answer with a head shim than to chase through minified code. A working server is `websites/stripe-press-maintenance-part-one/serve.py` in the Archival root.
- **A media URL that redirects can capture as a small HTML page under a `.mp4` name.** The verifier then plays nothing and reports nothing. Check stored size and magic bytes for media, and fetch from the redirect target.
- **A site's own feature flag beats patching its code.** Analytics is often guarded on a config value (`WRITE_KEY && analytics.init(...)`). Blanking that one string literal disables it at the author's own seam and leaves the logic untouched, which is far safer than excising a library that was minified together with application components.

Verification traps that let a broken archive pass:

- **CSS background images are invisible to `document.images`.** A texture referenced by `background: url(...)` — especially on a `::before`/`::after` — is never in the image audit, so a missing file renders as a flat background and passes. Walk computed styles including pseudo-elements, collect every `url()`, and force each through `new Image()`. Then assert a minimum count, so the collector itself cannot silently stop working.
- **A regex backreference inside a non-raw Python string is a control character**, not a backreference: `\1` is `\x01`. A URL-extracting regex written this way matches nothing and reports zero assets, which looks identical to a clean run. Use raw strings for embedded browser snippets, or avoid backreferences.
- **`document.fonts` reporting `loaded` is not proof a webfont renders.** It is a status flag, and it stays true for a face that never drew a glyph. Measuring text width is not enough either: a monospace face is within ~1px of generic `monospace` over a whole line because advance widths match by construction, and `next/font` deliberately installs a metric-matched `… Fallback` face. Worse, the capture machine often has the same font installed locally, so eyeballing the page cannot catch it. Rasterise a sample string to a canvas twice — once with the family plus its generic fallback, once with the fallback alone — and require the ink pixels to differ. Also assert each `.woff2` appears in `performance.getEntriesByType('resource')` with a non-zero `encodedBodySize`.
- **Ask for a face at its own weight, and only for faces the page actually uses.** Canvas defaults to weight 400; a site shipping a family at 300 only will silently fall back, and every family then rasterises identically to the fallback — which looks like a total font failure and is not. Equally, `document.fonts` reports `status: "unloaded"` for faces that do render, so it cannot be the test, and page builders declare families they never use, so iterating declared faces fails on ones that were correctly never downloaded. Read the family, weight and style each *visible run of text* is actually laid out with via `getComputedStyle`, and prove those.
- **Give webfonts time before measuring them.** `document.fonts.ready` resolves before faces that are only triggered by later layout have been requested; a check run too early sees one font file fetched instead of three and looks like a missing-asset bug that is not there. Settle for a beat after `ready`, then assert on the resource timings rather than on request logs captured during load.
- **Radix and other portal menus ignore synthetic `.click()`.** They listen for genuine pointer events, so a verifier that calls `element.click()` sees the menu never open and reports the feature as absent rather than broken. Drive them with real `Input.dispatchMouseEvent` press/release pairs at the element's centre. Anything reachable only through such a menu — exports, downloads, save destinations — is unverified until this is fixed.
- **Prove an export by catching the file.** Set `Page.setDownloadBehavior` to a temporary directory, click the real control, then assert on the bytes: PNG magic, width and height from the IHDR, and a plausible size. A button that appears to work and writes a 0-byte or placeholder file is the failure mode this catches.
- **Do not trust a screenshot for canvas content.** Read the pixels back and require some non-transparent ones. Equally, do not require *every* canvas to have painted — pages keep unmounted or zero-sized copies — assert at least one, and record the exception in the provenance file so it is not later mistaken for a missing check.

- **WordPress:** check `wp-sitemap.xml` before writing a parser. Its child maps often expose the complete bounded page inventory even when `/wp-json/` is unavailable. Media paths are predictable, but assume at least one asset breaks the pattern rather than silently trusting the count.
- **Framer static sites:** the sitemap is honest and the page set is small, but almost nothing else is in the HTML. Per-route and CMS-collection chunks are pulled with bare *relative* dynamic imports (`import("./xyz.mjs")`) from inside already-minified modules, so a crawler matching only `https://` misses them and every CMS-backed page renders its navigation and title with no console error to say why — resolve relative specifiers against each file's own URL. Framer also boots an authoring editor bar with `await import("https://framer.com/edit/init.mjs")` on every page load, which must be stubbed with a module exporting a `createEditorBar` that renders nothing, or the page throws and reaches for the network. Image variants differ only by query string (`?width=1230`), so fold a digest of the query into the filename rather than dropping it. Framer declares whole webfont families it never uses: testing every declared face fails on faces that were correctly never downloaded.
- **Framer CMS and runtime-named modules:** a CMS-backed section (a poster wall, a logo grid) loads a binary chunk built as `new URL("./<id>-chunk-default-0.framercms", "<module URL>").href.replace("/modules/", "/cms/")`, read with HTTP `Range` requests. Seed that URL by hand, serve `Range`, and keep the `new URL` base absolute (`location.origin+"/_fu/..."`): a root-relative base makes `new URL()` throw, the loader rejects silently, and the page's top Suspense boundary never hydrates. The page then *looks* complete from server HTML while every scroll-in section stays at `opacity: 0`, so check for React fibers on `#main > div`, not text. Phosphor icons load as `framer.com/m/phosphor-icons/<Name>.js@<version>`, named only at runtime; harvest the names from blocked requests, and note the file ends in a version, not `.js`. Framer's client router knows only slashless routes, so rewrite page links without a trailing slash.
- **Unicorn Studio WebGL embeds** (an `<iframe src="unicorn.studio/embed/<id>">`, common in Framer and Webflow footers): the iframe target is a two-line shim that loads `unicornStudio.umd.js` and calls `addScene({projectId})`. Everything real is fetched at runtime and invisible to an HTML scrape — the scene JSON from `storage.googleapis.com/unicornstudio-production/embeds/<id>`, and from inside that JSON a `modules` map of CDN extensions (`model-renderer.js`, which relatively imports a sibling `three-bundle.js`) plus any model, matcap or texture URL. Walk it explicitly. The runtime has a dependency-free seam for offline replay: `addScene({filePath: <elementId>})` reads the scene JSON out of a DOM element instead of fetching it, so build a local embed page around that rather than patching the minified runtime.

- **Tools whose archives precompute their derived data** (palettes, embeddings, transcripts, colour histograms) keep that data in JSON beside the media it was derived from. The derived data is usually a complete archive of the tool's actual work at a fraction of a percent of the media's size — one capture here was 47 MB of palettes describing 90,000 images that would have been 4.8 GB. Check whether the render path needs the source media or only the derived values before assuming a media crawl is in scope, and confirm the primary input path (file upload, paste, camera) is local and unaffected.

- **Cargo and other hosted builders:** embedded state can reveal the complete page inventory without a crawl. Cargo originals commonly live under `/t/original/`, asset delivery may require an ordinary browser user agent, and captured boot state may contain an origin redirect that must be disabled and documented for local replay.

Common implementation traps:

- assets embedded in JSON, CSS, template literals, service workers, or runtime-generated URLs;
- replacement strings interpreting special dollar sequences—use function replacements;
- Python 3.14+ surfacing `socket.TimeoutError` directly from `urllib.request`; catch timeout, connection, and OS errors as well as `URLError`/`HTTPError` in resumable crawlers;
- infinite animation loops defeating virtual-time waits—use bounded command timeouts;
- WebGL buffers reading blank through DOM canvas APIs—capture through the compositor;
- lazy media needing a bounded scroll pass before completeness checks;
- a local archive that looks correct only because service-worker or browser cache still contains the live site;
- `requestAnimationFrame` not firing in a hidden or backgrounded tab, so entrance animations never run and the page looks broken when driven from a background window — check `document.visibilityState` before believing the screenshot;
- a network shim that only wraps `fetch` and `XMLHttpRequest`, while the page appends analytics as `<script>` elements — those never touch either API, so the archive loads them from the live network and the shim reports a clean run. Intercept the `src`/`href` setters and `setAttribute` on script, image, iframe, media and link elements too, and point blocked URLs at `about:blank` so the loader's load/error events still fire;
- a network shim that throws synchronously from `XMLHttpRequest.open` — real offline fails asynchronously with status 0, and the throw takes down whatever effect was running;
- asset paths containing spaces (`/textures/256x256/Super Perlin/…`), which a character-class URL regex clips silently mid-path — extract from quoted string literals as well, and discard matches with no file extension;
- a site that serves a framework 404 page under HTTP 200 to a non-browser user agent while serving the real page to a browser one: probe with both before concluding a route does not exist;
- capturing and rewriting into the same directory: once URLs are rewritten to local paths, a later fix to the crawler can never re-walk the asset graph, because every reference it needed to follow is gone. Download to a pristine tree and derive the browsable one from it, hardlinking so a capture with hundreds of megabytes of video does not cost two copies (and unlinking before every write, or the rewrite edits the pristine capture through the shared inode);
- a resumable crawler that seeds its "already seen" set from resume state: it then skips *extraction* for files already on disk, not just the download, so a crawler fix reaches nothing. Seed it empty and let the on-disk check skip the network instead;
- half-built template literals (`https://host/${i}`) and bundler comments naming unpublished `node_modules` paths, harvested by a URL regex over minified code and then reported as capture failures — filter them before queueing, or the failure list stops meaning anything;
- `net::ERR_ABORTED` on a lazily-loaded iframe's own assets when the verifier navigates to the next route, which is teardown rather than a missing file — exercise the lazy subresource on its own page, where nothing competes with it, and assert its bytes arrived;
- a flat minimum on rendered text as a hydration check: some pages really are a headline and a video. Compare against the visible text in that route's own stored HTML;
- clicking a link inside a long awaited `Runtime.evaluate` when the site does a real document navigation — the execution context is torn down mid-call and CDP reports "Inspected target navigated or closed". Fire the click, then wait and query separately;
- assets addressed by a slug assembled at runtime (`/logos/<variant>/<slug>.png`), where only the slug set appears in the bundle as a literal.
- Chrome's `--host-resolver-rules=MAP * ~NOTFOUND` applies to the loopback literal too, so a verifier that serves the archive over HTTP cannot reach its own server and every page reports `net::ERR_NAME_NOT_RESOLVED` for `127.0.0.1`. Append `,EXCLUDE 127.0.0.1`. A `file://` verifier never hits this, so it looks like the archive is broken rather than the flag;
- `mirror.py` encodes a query string into the filename (`style.css?v=3` becomes `style__qv_3.css`), but a static server strips the query and looks for `style.css` — a 404 for a file that is plainly on disk. Strip `?v=` cache-busting from the references when building the servable tree, and check that the plain name exists;
- a network shim that refuses cross-origin requests will also refuse a *same-host, different-port* helper the site talks to in development (`127.0.0.1:8011`), which is correct — but only if you then disable the feature in the UI. A refused promise deep in a render path shows up as a spinner that never resolves.

## Mux video (mux-player / HLS)

- The player loads only on interaction (lightbox, play button). A live headless pass that clicks it is the only reliable inventory: it shows the master playlist on `stream.mux.com`, signed renditions and chunks on CDN hosts, posters and storyboards on `image.mux.com`, the Mux Data beacon on `litix.io`, and Google's Cast SDK on `gstatic.com`.
- Static MP4 renditions (`/high.mp4`, `/capped-1080p.mp4`) are often not enabled (404). Copy the highest HLS rendition and its segments instead, and rewrite the playlists to **absolute** local paths. hls.js inside mux-player resolved relative ones against the page.
- Map `stream.mux.com/<id>.m3u8` and `image.mux.com/<id>/...` to local files in a fetch/XHR/setter shim. The storyboard `<track>` comes from a shadow-DOM template, so no setter sees it. Set the `storyboard-src` attribute on each `mux-player` instead.
- Worked example: `websites/operate.so/2026-10-14/tools/` (`fetch_mux.py`, `offline-shim.js`, `serve.py`).
