# Project and personal targets

## Shared project instructions

Highest-value content:

- verified commands that cannot be inferred reliably;
- conventions that differ from tool defaults;
- non-obvious failure modes and environment boundaries;
- repository history/review etiquette;
- definition of done and proportional verification;
- scoped authority and destructive/external-action rules.

Prefer nested/scoped files for subprojects when the active host truly loads them by path or demand. Do not recite the directory tree or dependency list.

## Personal working relationship

Include only supported sections:

- identity and attribution facts;
- desired register and output shape;
- how disagreement and uncertainty should be expressed;
- affect/enthusiasm preference without scripting a persona;
- autonomy boundaries and the short ask-first list;
- machine safety posture and environment-specific traps;
- a concise note to future instances only if the user wants it and it changes behavior.
